## P0-3：fetchTaskTree 响应解析修复

### 当前行为

**前端** `frontend/src/api/issues.ts` 第 163-166 行：

```typescript
export async function fetchTaskTree(issueId: string): Promise<TaskTreeNode[]> {
  const res = await get<TaskTreeNode[]>(`/issues/${issueId}/task-tree`);
  return Array.isArray(res) ? res : [];
}
```

**后端** `GET /{issue_id}/task-tree` 实际返回：

```json
{
  "issue_id": "xxx",
  "nodes": [
    { "id": "n1", "name": "分析需求", "status": "pending", "children": [] }
  ],
  "from_db": true
}
```

`res` 是对象，`Array.isArray(res)` 为 `false` → 永远返回 `[]` → **任务树 UI 永远显示"暂无子任务"**。

### 修复方案

**修改文件**: `frontend/src/api/issues.ts`

```typescript
// 修改前
export async function fetchTaskTree(issueId: string): Promise<TaskTreeNode[]> {
  const res = await get<TaskTreeNode[]>(`/issues/${issueId}/task-tree`);
  return Array.isArray(res) ? res : [];
}

// 修改后
export async function fetchTaskTree(issueId: string): Promise<TaskTreeNode[]> {
  const res = await get<any>(`/issues/${issueId}/task-tree`);
  const nodes = Array.isArray(res?.nodes) ? res.nodes : [];
  // 递归构建 children（后端返回扁平结构，前端需构建树）
  return buildTaskTree(nodes);
}

/** 将扁平节点列表构建为树结构 */
function buildTaskTree(nodes: any[]): TaskTreeNode[] {
  const map = new Map<string, TaskTreeNode>();
  const roots: TaskTreeNode[] = [];

  for (const n of nodes) {
    map.set(n.id, { ...n, children: [] });
  }

  for (const n of nodes) {
    const node = map.get(n.id)!;
    if (n.parent_id && map.has(n.parent_id)) {
      map.get(n.parent_id)!.children.push(node);
    } else {
      roots.push(node);
    }
  }

  return roots;
}
```

### 修改文件清单

| 文件 | 改动类型 | 说明 |
|------|----------|------|
| `frontend/src/api/issues.ts` | 修改 `fetchTaskTree` + 新增 `buildTaskTree` | 解析 `{ nodes }` 响应，构建树结构 |

### 风险

- **低风险**：只改前端 API 解析逻辑，不影响后端
- 需确认后端 `task-tree` 端点返回的 `nodes` 中是否含有 `parent_id` 字段（用于构建树）

## P0-2：update_issue 后端校验

### 当前行为

**后端** `backend/app/api/issues.py` 第 155-169 行：

```python
@router.patch("/{issue_id}")
async def update_issue(...):
    issue = await _get_issue(db, issue_id)
    for field, value in body.model_dump(exclude_unset=True).items():
        if value is not None:
            setattr(issue, field, value)  # ← 直接写入，无验证
    await db.commit()
```

若传入不存在的 `assigned_agent_id`：
- SQLite + SQLAlchemy：若 FK 约束启用，commit 时报错
- SQLite 默认不强制 FK：静默写入无效值 → 后续派发时查不到 Agent → **崩溃**

### 修复方案

**修改文件**: `backend/app/api/issues.py`

在 `update_issue` 中添加 `assigned_agent_id` 校验：

```python
@router.patch("/{issue_id}")
async def update_issue(
    issue_id: str,
    body: IssueUpdate,
    db: AsyncSession = Depends(get_db),
):
    """更新 Issue"""
    issue = await _get_issue(db, issue_id)

    data = body.model_dump(exclude_unset=True)
    for field, value in data.items():
        if value is not None:
            # 校验 assigned_agent_id 有效性
            if field == "assigned_agent_id" and value is not None:
                result = await db.execute(
                    select(Agent).where(Agent.id == uuid_module.UUID(value))
                )
                if not result.scalar_one_or_none():
                    raise HTTPException(400, f"Agent {value} 不存在")
            setattr(issue, field, value)

    await db.commit()
    await db.refresh(issue, ["assigned_agent", "attachments"])
    return _issue_to_response(issue)
```

| 文件 | 改动类型 | 说明 |
|------|----------|------|
| `backend/app/api/issues.py` | 修改 `update_issue` | 添加 `assigned_agent_id` 存在性校验 |

### 风险

- **低风险**：只新增校验逻辑，不影响正常流程
- 需确认 `Agent` 模型已导入（当前文件头部已有 `from app.models.agent import Agent`）

## P0-7：_execute_llm 错误处理修复

### 当前行为

**后端** `backend/app/runtime/execution_engine/node_executor.py` 第 206-211 行：

```python
except Exception as e:
    logger.exception("LLM call failed in node '%s'", node.id)
    state.setdefault("messages", []).append({
        "role": "system",
        "content": f"LLM call failed: {e}",
    })
    # ← 没有 raise，没有 error_count++，没有 workflow_status 设置
```

LLM 调用失败后：
- 工作流继续执行后续节点
- 后续节点若有 LLM/Tool 依赖，收到的是错误字符串而非有效内容
- 用户完全不知道 LLM 调用已失败

对比 Tool 节点失败处理（正确）：

```python
# Tool 节点
except Exception as e:
    result = ToolResult(error=str(e), ...)
state["error_count"] = state.get("error_count", 0) + 1
```

### 修复方案

**修改文件**: `backend/app/runtime/execution_engine/node_executor.py`

```python
# 修改前
except Exception as e:
    logger.exception("LLM call failed in node '%s'", node.id)
    state.setdefault("messages", []).append({
        "role": "system",
        "content": f"LLM call failed: {e}",
    })

# 修改后
except Exception as e:
    logger.exception("LLM call failed in node '%s'", node.id)
    state.setdefault("error_count", 0)
    state["error_count"] += 1
    state.setdefault("messages", []).append({
        "role": "system",
        "content": f"LLM call failed: {e}",
    })
    # 达到最大错误数，标记工作流失败
    max_errors = node.config.get("max_errors", 3)
    if state["error_count"] >= max_errors:
        state["workflow_status"] = "failed"
        logger.error(
            "Workflow %s failed: error_count=%d >= max_errors=%d",
            state.get("task_id", "unknown"),
            state["error_count"],
            max_errors,
        )
```

### 修改文件清单

| 文件 | 改动类型 | 说明 |
|------|----------|------|
| `backend/app/runtime/execution_engine/node_executor.py` | 修改 `_execute_llm` | 失败后 increment error_count，达到阈值设置 workflow_status=failed |

### 风险

- **低风险**：只改错误处理分支，正常流程不受影响
- `workflow_status = "failed"` 需要上游执行引擎检查该字段并终止执行（需确认 `LangGraphAdapter` 或 `Scheduler` 是否检查此字段）

## P0-6：submit_task_with_workflow 修复

### 当前行为

**后端** `backend/app/runtime/kernel.py` 第 310-347 行：

```python
async def submit_task_with_workflow(self, task_request: TaskRequest) -> str:
    # 1. 提交任务（使用默认空工作流 start→end）
    task_id = await self.submit_task(task_request)
    #    ↑ 内部构建了 ScheduledTask(workflow_spec=default_workflow)
    #    ↑ 已入队到 scheduler.queue

    # 2. 生成真实 Workflow（调用 LLM，耗时）
    workflow_spec = await self.generate_workflow(...)

    # 3. 保存到内存字典（但 scheduler 队列中的 ScheduledTask 仍指向 default_workflow）
    if workflow_spec:
        self._workflows[task_id] = workflow_spec
        task = self._tasks.get(task_id)
        if task:
            task.workflow_id = task_id

    return task_id  # ← scheduler 执行时用的是 default_workflow，不是真实 workflow
```

**执行链路**：

```
submit_task_with_workflow()
    │
    ├─ submit_task()
    │   └─ scheduler.submit(ScheduledTask(workflow_spec=default_workflow))
    │       └─ 入队 TaskQueue ←─────────┐
    │                                           │
    ├─ generate_workflow()                      │
    │   └─ self._workflows[task_id] = ...   │
    │                                           │
    └─ return task_id                          │
                                                │
                                    Scheduler 执行 ↓
                                        ScheduledTask.workflow_spec
                                        = default_workflow (start→end)
                                        ← 真实 workflow 被丢弃
```

### 修复方案

**核心思路**：在 `submit_task` 完成入队 **之前**，若调用方是 `submit_task_with_workflow`，应先生成 workflow。

**方案 A（推荐）：先生成 Workflow，再入队**

修改 `submit_task` 支持可选 `workflow_spec` 参数；`submit_task_with_workflow` 先生成 workflow，再传入 `submit_task`。

```python
# kernel.py

# 1. 修改 submit_task 接受可选 workflow_spec
async def submit_task(self, task_request: TaskRequest, workflow_spec: Optional[Any] = None) -> str:
    # ... 原有逻辑 ...

    # 构建 ScheduledTask 时使用传入的 workflow_spec（若有）
    from app.runtime.execution_engine.workflow_schema import WorkflowSpec, NodeSpec, EdgeSpec, NodeType
    if workflow_spec is None:
        default_workflow = WorkflowSpec(
            name=f"task-{task_id[:8]}",
            nodes=[NodeSpec(id="start", type=NodeType.START), NodeSpec(id="end", type=NodeType.END)],
            edges=[EdgeSpec(source="start", target="end")],
        )
        workflow_spec = default_workflow

    scheduled = ScheduledTask(
        task_id=task_id,
        capability=capability,
        workflow_spec=workflow_spec,  # ← 使用传入的 workflow
        priority=task_request.priority,
        metadata=task_request.metadata,
    )
    await self.scheduler.submit(scheduled)
    # ...


# 2. 修改 submit_task_with_workflow：先生成 workflow，再提交
async def submit_task_with_workflow(self, task_request: TaskRequest) -> str:
    """
    W17: 提交任务并自动生成 Workflow。
    先生成 Workflow，再入队（避免 scheduler 执行空工作流）。
    """
    # 1. 先生成 Workflow（同步等待 LLM 完成）
    workflow_spec = await self.generate_workflow(
        goal_text=task_request.goal_description,
        params={
            "task_name": task_request.goal_description[:30],
            "model_name": getattr(self.model_router, "default_model", "gpt-4"),
        },
    )

    # 2. 使用真实 Workflow 提交任务
    task_id = await self.submit_task(task_request, workflow_spec=workflow_spec)

    # 3. 保存 workflow 引用（用于后续查询）
    if workflow_spec:
        self._workflows[task_id] = workflow_spec
        task = self._tasks.get(task_id)
        if task:
            task.workflow_id = task_id

    return task_id
```

**风险**：

- `generate_workflow` 是 async 调用 LLM，会阻塞 `submit_task_with_workflow` 直到 LLM 返回
- 若 LLM 生成失败（`workflow_spec = None`），会 fallback 到 `default_workflow`（与当前行为一致）

**方案 B：Scheduler 执行前检查 Kernel._workflows（不推荐）**

在 `Scheduler._execute_workflow` 中，执行前检查 `kernel._workflows.get(task_id)`，若有则使用。

缺点：引入 Scheduler ↔ Kernel 双向依赖，架构混乱。

| 文件 | 改动类型 | 说明 |
|------|----------|------|
| `backend/app/runtime/kernel.py` | 修改 `submit_task` | 新增可选 `workflow_spec` 参数 |
| `backend/app/runtime/kernel.py` | 修改 `submit_task_with_workflow` | 先生成 workflow，再入队 |

### 风险

- **中等风险**：`submit_task_with_workflow` 现在是阻塞等待 LLM 生成，会增加任务提交延迟
- 若 LLM 生成超时，`generate_workflow` 可能抛异常 → 需要 try-catch 包裹，fallback 到 `default_workflow`
- 需验证 `WorkflowSpec` 对象可序列化（因 ScheduledTask 可能被 checkpoint 保存）

## 附录：后端 task-tree 端点返回格式确认

当前 `get_issue_task_tree` 返回的 `nodes` 是**扁平结构**：

```json
{
  "issue_id": "xxx",
  "nodes": [
    { "id": "n1", "parent_id": null, "name": "分析", ... },
    { "id": "n2", "parent_id": "n1", "name": "编写代码", ... }
  ]
}
```

前端 `buildTaskTree` 需根据 `parent_id` 构建树形结构。

`TaskTreeNode` 接口定义（前端）：

```typescript
export interface TaskTreeNode {
  id: string;
  name: string;
  title: string;
  role: string;
  status: string;
  kanban_column?: string;
  agent_name?: string;
  children: TaskTreeNode[];  // ← 递归字段
}
```
