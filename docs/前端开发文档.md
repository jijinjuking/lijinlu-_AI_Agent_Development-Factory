## 一、前端定位

前端是 AI Agent OS 的**唯一可视化入口**，核心职责：

```
用户
  ↓
前端 UI
  ↓
API Gateway ← → WebSocket 实时推送
  ↓
Runtime Kernel（后端）
  ↓
多 Agent 执行
```

**前端必须解决的黑盒问题：**
1. Agent Loop 执行过程不可见 → 执行链路可视化
2. 多 Agent 协作状态不透明 → 实时协作看板
3. 成本/质量/费用无追踪 → 统计面板
4. 三层记忆无 UI → 记忆管理界面
5. Skill 无市场界面 → Skill 市场

## 二、技术栈选型

| 层级 | 技术 | 理由 |
|------|------|------|
| **桌面壳** | Tauri 2.x（Rust） | 比 Electron 轻量（<10MB），原生性能，直接访问本地文件系统 |
| **框架** | React 18 + TypeScript | 组件化、类型安全 |
| **构建** | Vite | 快，HMR 好用，Tauri 原生集成 |
| **状态管理** | Zustand | 轻量，适合实时数据 |
| **数据流** | TanStack Query | API 缓存 + 轮询 |
| **路由** | React Router v6 | 标准方案 |
| **UI 组件** | Ant Design 5.x | 企业级，组件全 |
| **图表/可视化** | ECharts + ReactFlow | 执行链路图用 ReactFlow，统计用 ECharts |
| **实时通信** | WebSocket（原生）| 后端推送 Agent 状态 |
| **代码编辑器** | Monaco Editor | 展示/编辑生成代码 |
| **样式** | CSS Modules + Ant Design Token | 避免样式冲突 |
| **Rust 后端能力** | Tauri Commands | Rust 侧直接读写本地文件、调用系统 API |

│                                         │
│  ▼ Root (Intent Router)                │

│    │    │   输出：1,800 tokens         │
│    │    │   耗时：3.2s                 │
│    │    └─ 输出：任务拆解结果 JSON     │
│    │                                     │
│    ├─ ▶ Node: CoderAgent (x3 并行)  │
│    │    ├─ LLM Call (DeepSeek)        │
│    │    ├─ Tool Call: ReadFile        │
│    │    ├─ Tool Call: WriteFile       │
│    │    └─ 输出：3 个文件              │
│    │                                     │

**技术实现：**
- 用 ReactFlow 渲染执行链路图（节点 = Agent/工具调用，边 = 数据流）
- 左侧树状展开/折叠（类似 LangSmith Traces 界面）
- 点击节点显示详细信息（输入/输出/耗时/token/费用）
- 支持「重新运行此节点」（开发调试用）

### 4.4 Pipeline 编排页面（流程图编辑）

**功能：** 可视化编辑 LangGraph StateGraph，类似 n8n / LangSmith Hub

```
工具栏：
  [Planner] [Coder] [Debug] [Tester] [HumanReview]

画布：
  [Planner] --(需求文档)--> [Coder] --(代码)--> [Debug]
                                                  |
                                          (测试失败) --backedge--> [Coder]
                                          (测试通过) --> [Deploy]

右侧属性面板：
  - 节点类型
  - 使用的 LLM 模型
  - 系统 Prompt
  - 工具列表
  - 条件分支规则
```

**技术实现：**
- ReactFlow 自定义节点
- 每个节点对应 LangGraph 的一个 `Node`
- 边对应 LangGraph 的 `Edge`（包含条件函数）
- 「保存」→ 生成 `pipeline.json` → 后端加载为 LangGraph StateGraph

## 五、核心组件设计

### 5.1 `AgentKanban`（协作看板）

```typescript
// 类型
interface AgentTask {
  id: string;
  title: string;
  agentType: 'planner' | 'coder' | 'debug' | 'tester' | 'deploy';
  status: 'todo' | 'running' | 'reviewing' | 'done' | 'rejected';
  startTime?: number;
  endTime?: number;
  tokenUsage: { input: number; output: number };
  cost: number;  // ¥
  outputFiles?: string[];
  error?: string;
}

// 实时更新
useEffect(() => {
  const ws = new WebSocket('ws://localhost:8000/ws/kanban');
  ws.onmessage = (e) => {
    const update: AgentTask = JSON.parse(e.data);
    updateTask(update);  // Zustand store
  };
  return () => ws.close();
}, []);
```
